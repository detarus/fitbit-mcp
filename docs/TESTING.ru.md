# Проверка alpha на Mac

Это первая версия для проверки. Реальный Google-аккаунт пока не проверен. CI на синтетических данных и вход в аккаунт — разные проверки. Нет опубликованного npm-релиза.

## 1. Сборка и демо без Google

Нужны Git, Node.js 24 LTS и pnpm 10.20.0. При отсутствии pnpm: npm install --global pnpm@10.20.0.

```bash
git clone https://github.com/detarus/fitbit-mcp.git
cd fitbit-mcp
pnpm install --frozen-lockfile
pnpm check
node dist/cli.js demo-check
```

Если начальный lockfile ещё не появился после CI, один раз выполните pnpm install --no-frozen-lockfile. Не заменяйте frozen-install при обычном обновлении зависимостей.

Ожидаемый результат demo-check: demo=true, googleRequests=0, сохранённое блюдо имеет state=verified, повтор не создаёт новую запись, удаление имеет state=deleted. Демонстрация полностью синтетическая.

Для проверки самого MCP в режиме демо:

```bash
codex mcp add fitbit-demo -- node "$PWD/dist/cli.js" serve --demo
claude mcp add --scope user --transport stdio fitbit-demo -- node "$PWD/dist/cli.js" serve --demo
```

Node должен быть в PATH клиента. Для надёжного абсолютного пути замените node результатом node -p process.execPath. Перезапустите клиента и попросите вызвать fitbit_status. Убедитесь, что demo=true. Не подключайте демо и реальный сервер под одним именем.

## 2. Настройка Google

1. Войдите в Google Health на телефоне под аккаунтом Fitbit и синхронизируйте браслет.
2. В Google Cloud создайте свой проект и включите Google Health API.
3. Настройте OAuth consent screen: External, Testing; добавьте свой аккаунт в Test users.
4. В Data access добавьте полные scopes с префиксом https://www.googleapis.com/auth/googlehealth.:
   - activity_and_fitness.readonly
   - health_metrics_and_measurements.readonly
   - sleep.readonly
   - nutrition.readonly
   - settings.readonly
5. Для питания и воды добавьте nutrition.writeonly.
6. Создайте OAuth client типа Desktop app и скачайте JSON в приватную папку вне репозитория.

Настройка требует ручного входа владельца аккаунта. Не присылайте JSON, client secret или токены в чат. Для Desktop client приложение само выбирает loopback-порт; URI веб-приложения сюда не подходит. Подробности: https://developers.google.com/health/setup.

## 3. Авторизация

Замените путь на свой скачанный JSON:

```bash
node dist/cli.js setup --credentials "/absolute/path/to/client.json" --nutrition-write
node dist/cli.js auth
node dist/cli.js doctor --live
```

Без записи уберите --nutrition-write. Повторный setup сбрасывает локальные токены и требует auth. В браузере разрешайте только нужные доступы: частичное согласие должно давать понятную ошибку нужного домена, а не ломать весь сервер.

Ожидается configured=true, connected=true и live.reachable=true. В Testing refresh grant обычно истекает через семь дней: тогда снова auth. Команда auth --no-open печатает URL для самостоятельного открытия в браузере; не публикуйте этот URL.

На Mac конфигурация и токены находятся в ~/Library/Application Support/fitbit-mcp: каталог 0700, файлы 0600. Это локальные файлы без шифрования самим приложением. В этой папке также хранятся журналы операций с данными питания.

## 4. Подключение реальных клиентов

Убедитесь, что codex или claude уже установлен:

```bash
node dist/cli.js install --client codex
node dist/cli.js install --client claude
```

Команда регистрирует абсолютные пути к Node и собранному серверу. Перезапустите клиентов. Не удаляйте и не перемещайте репозиторий после регистрации; при переносе повторите install.

Первые запросы:

- «Вызови fitbit_status и покажи доступы. Демо должно быть выключено».
- «Покажи подключённые устройства».
- «Покажи активность с 2026-10-10 по 2026-10-17, конец периода не включается».
- «Получи сон за тот же период; не заменяй пропуски нулями».

Даты примера замените актуальными. Сравните семь дней с приложением по локальным датам, единицам и пропускам. Не отправляйте сырые ответы в GitHub.

## 5. Первая запись питания

Начните с одной понятной записи, которую действительно хотите добавить. В чате:

«Создай черновик обеда: куриная грудка 100 г, 165 ккал, Б 31 г, Ж 3.6 г, У 0 г. Источник — мои данные. Используй сегодняшнюю дату и мой часовой пояс; время обеда 13:00. Пока не сохраняй».

Клиент должен определить точную дату/offset, вызвать fitbit_request_id, затем fitbit_preview_meal. Покажите ему скилл skills/nutrition/SKILL.md, если он не установлен.

Вес порции в этой alpha сохраняется в названии блюда, например «Chicken (100 g)»; КБЖУ относятся ко всей порции. Отдельную единицу порции из каталога API пока не подставляем.

Проверьте черновик и скажите «сохрани этот черновик». Ожидается fitbit_commit и state=verified. Откройте дневник питания Google Health и проверьте название и КБЖУ. Затем попросите повторно проверить ту же операцию: новая запись не должна появиться.

Если это была тестовая запись, скажите «удали запись, созданную этой операцией», после чего проверьте отсутствие записи в приложении. Для воды повторите с 250 мл и fitbit_preview_water.

При unknown, sending или deleting остановите повторы и проверьте приложение вручную. Автоматическое разрешение неопределённых исходов в этой alpha не реализовано. Исправление ручных КБЖУ выполняется удалением известной записи и созданием новой; это не атомарная операция.

## 6. Плагины со скиллами (дополнительная проверка)

После сборки можно установить локальный бинарник:

```bash
npm install --global .
```

В репозитории есть .claude-plugin/plugin.json, .codex-plugin/plugin.json, .mcp.json и общие skills/. MCP в плагине запускает fitbit-mcp из PATH. В Claude Code для локальной проверки:

```bash
claude --plugin-dir "$PWD"
```

Не регистрируйте одновременно плагин и ручной MCP с одним сервером. Полная установка плагинов в обоих клиентах пока требует проверки. Если локальный плагин недоступен, используйте install из раздела 4, а инструкции skills/ загрузите как проектные/пользовательские скиллы по документации клиента.

## 7. Что сообщить по итогам

Достаточно: версия macOS, версия Node, версии Codex/Claude Code, прошли ли demo, auth, чтение, запись и удаление; при ошибке — только её code и HTTP status. Не присылайте токены, client secret, идентификаторы аккаунта, подробные показатели или полный журнал.

Обычные ChatGPT/Claude web/mobile пока не подключены. Фото можно использовать только в клиенте с поддержкой изображений и этого MCP; оценки порций приблизительны.

Отключение: node dist/cli.js disconnect удаляет локальные токены. Доступ Google отзывается отдельно в Google Account → Security → Third-party connections. Журналы остаются для сверки и предотвращения дублей; удаляйте их вручную только после разрешения неопределённых операций.
